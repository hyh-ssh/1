# 修改说明：统一登录后用户名直接使用学号

## 1. 目标

学生通过学校统一身份认证（OIDC）首次登录后，本地账号名**就是学号**（如 `256530319`），
而不是原先由 issuer+subject 派生出来的 `oidc-xxxxxxxx...`。

要求同时满足：

- 用户名可读、可与学生身份对上；
- **用户名不承担账号识别职责** —— 换名、重名都不会导致"顶替别人账号"；
- 学号被无关账号占用时，登录**不能失败**。

## 2. 只改了两个文件

| 文件 | 改动性质 |
|---|---|
| `backend/internal/httpapi/oidc.go` | 首次登录时"叫什么名字" |
| `backend/internal/store/oidc.go` | 这个名字"怎么落库" |

未改动的部分：数据库表结构、`migrations/` 下任何脚本、前端代码、
环境变量与配置文件、Dockerfile、`docker-compose.yml`。**本次改动与部署环境无关。**

## 3. 文件一：`backend/internal/httpapi/oidc.go`

### 3.1 调用点（第 251 行）

```go
// 前
Username:    oidcUsername(issuer, claims.Subject),
// 后
Username:    oidcLocalUsername(issuer, claims),
```

### 3.2 新增 `oidcLocalUsername`（第 408–413 行）

```go
// oidcLocalUsername chooses the local account name a first-time OIDC login gets.
// A usable preferred_username is used verbatim, because that is the identifier
// the campus IdP already publishes (a student/staff number) and the console
// renders the local username rather than the display name. Identity is still
// bound on issuer+subject through oidc_identities: the username never links
// accounts, and the store appends a deterministic suffix when the requested
// name is already held by an unrelated account.
func oidcLocalUsername(issuer string, claims oidcClaims) string {
	if name := normalizeOIDCUsername(claims.PreferredUsername); name != "" {
		return name
	}
	return oidcUsername(issuer, claims.Subject)
}
```

**逻辑**：IdP 传来的 `preferred_username` 通过校验就用它（学校 CAS 在
`preferred_username` 里填的就是学号）；不通过则退回原有派生逻辑。

### 3.3 新增 `normalizeOIDCUsername`（第 420–438 行）

```go
// normalizeOIDCUsername accepts a preferred_username only when it is safe to
// store and display as an account name: 1-32 characters of ASCII letters,
// digits, dot, underscore or hyphen, not starting with punctuation. Anything
// else falls back to the derived name instead of being repaired, so a hostile
// claim cannot be reshaped into something that reads like another account.
func normalizeOIDCUsername(value string) string {
	trimmed := strings.TrimSpace(value)
	if len(trimmed) == 0 || len(trimmed) > 32 {
		return ""
	}
	for i := 0; i < len(trimmed); i++ {
		ch := trimmed[i]
		switch {
		case ch >= 'a' && ch <= 'z', ch >= 'A' && ch <= 'Z', ch >= '0' && ch <= '9':
		case ch == '.', ch == '_', ch == '-':
			if i == 0 {
				return ""
			}
		default:
			return ""
		}
	}
	return trimmed
}
```

**校验规则**：长度 1–32；仅允许 ASCII 字母、数字、`.`、`_`、`-`；首字符不得是标点。

**设计取舍**：不合规时**整体放弃**并退回派生名，而不是把非法字符"清洗掉"。
因为把一段外部可控的字符串修剪成"看起来像某个已有账号"的名字，
本身就是一条身份混淆路径。宁可显示得难看，也不给人以可乘之机。

### 3.4 保留原函数 `oidcUsername`（第 442–445 行，未删除）

```go
func oidcUsername(issuer, subject string) string {
	digest := sha256Hex(issuer + "\x00" + subject)
	return "oidc-" + digest[:24]
}
```

作为兜底路径保留：claim 缺失、不合规、或未来 IdP 变更时，行为与改造前完全一致。

## 4. 文件二：`backend/internal/store/oidc.go`

### 4.1 插入用户：冲突不报错（第 90 行）

```sql
INSERT INTO users(...) ... ON CONFLICT (username) DO NOTHING RETURNING id
```

### 4.2 重名兜底（第 112–121 行）

```go
// Otherwise the requested name is already held by a different account
// (for example a locally created account whose username equals the
// IdP's preferred_username). Keep the requested name as the readable
// stem and append a deterministic suffix derived from the identity, so
// the new account is always provisioned instead of failing the login.
fallback := user.Username + "-" + oidcIdentitySuffix(issuer, subject)
if err := insertUser(fallback); err != nil {
	return nil, err
}
user.Username = fallback
```

完整判定顺序：

1. 先按 `(issuer, subject)` 查身份；
2. **查到** → 说明是并发注册，直接返回已有账号（**不算重名，不加后缀**）；
3. **没查到** → 学号确实被别的账号占着，此时把学号作为可读主干，
   追加确定性后缀，**仍然把新账号建出来**，登录不失败。结果形如 `256530319-a1b2c3`。

### 4.3 新增 `oidcIdentitySuffix`（第 172–175 行）

```go
// oidcIdentitySuffix returns a short, deterministic token derived from the
// issuer/subject pair. It disambiguates a requested username that an unrelated
// account already holds, without introducing randomness: the same identity
// always resolves to the same suffixed name.
func oidcIdentitySuffix(issuer, subject string) string {
	sum := sha256.Sum256([]byte(issuer + "\x00" + subject))
	return hex.EncodeToString(sum[:])[:6]
}
```

**确定性、无随机数**：同一身份永远得到同一个后缀名（重复登录结果稳定），
不同身份不会相互碰撞。不用随机数是为了避免"每次登录名字都不一样"。

### 4.4 身份绑定保持原样（第 133–136 行，未改）

```sql
INSERT INTO oidc_identities(issuer, subject, user_id)
VALUES($1,$2,$3) ON CONFLICT (issuer, subject) DO NOTHING RETURNING user_id
```

**账号始终由 `(issuer, subject)` 决定**，用户名只是展示用的标签。
因此"用户名 = 学号"不会引入任何越权或冒用通道。

## 5. 安全边界小结

| 问题 | 处理 |
|---|---|
| 用户名显示成学号，会不会让别人借此登进我的号？ | 不会。身份绑定在 `(issuer, subject)`，与用户名无关。 |
| IdP 传来非法的 `preferred_username` 怎么办？ | 整体拒绝，退回派生名（`oidc-` + 摘要）。 |
| 学号已被本地账号占用怎么办？ | 加确定性后缀另建账号，登录不失败，也不动原账号。 |
| 并发首次登录（同一人两处同时登）？ | `ON CONFLICT` + 事务内复检，输的一方回滚自己刚建的账号，返回赢家。 |
| 重复登录会不会每次生成新账号？ | 不会。第二次起命中 `oidc_identities`，直接复用。 |

## 6. 已知边界（不属于本次改动范围）

OIDC 的 `issuer` 字符串包含**授权服务的地址**。若同一套 IdP 通过两个不同地址
（例如内网 IP 与对外域名）提供 OIDC，则会得到两个不同的 `issuer`，
从而被视作两个不同身份、各建一个账号。这属于 **IdP 侧 issuer 配置**的问题，
不由本次代码改动引入，也无法在客户端侧绕过。
