## F01 · 已确认：免费调用仍正常记录用量

- 用户决定原文：“按照免费调用仍正常记录用量来修改功能”。
- 确认方向：支持免费调用；免费请求仍正常保存请求记录、实际用量与调用结果，不能因不扣积分而省略计量。
- 不将“免费调用”与“没有用量”混为一谈；请求结果与结算/免费状态需要能够区分。
- 免费不代表上游成本一定为零；不凭空估计价格或伪造已结算金额。
- 不自动追溯扣费；不把上一轮建议的“缺价一律拦截”作为已获批准的实现要求。
- 免费、未定价与结算失败的具体字段和价格表单契约，在后续价格/模型就绪相关需求中对齐，不擅自把缺价都等同显式免费。
- 预期验收：免费请求成功后仍可查询其实际用量和结果；不把免费流量显示为零 Token，不错误标成收费结算成功。

## F02 · 已确认方向：先移除用户组功能

- 用户决定原文：“这个问题简单处理，先去掉这个用户组功能，用户、用户组功能后面会有一个大重构”。
- 本轮不实施上一轮提出的基础用户组、待授权审批或新的分组权限系统；用户和用户组的大重构另行规划。
- 用户组入口、管理流程及依赖该功能的文案属于移除范围；不把本次决定扩展为删除用户账号、移除登录或个人密钥能力。
- 用户组不等于模型组；本条不自动授权连带删除模型组，其用途在模型服务相关需求中再对齐。
- 实施边界须在总计划中明确：旧用户组是否仍参与运行期授权、移除后的实际权限如何变化。不能只隐藏界面却留下无法管理的隐性拦截，也不能未经确认静默扩大既有权限。
- 默认保留已有分组历史数据供后续重构使用；是否清理数据库不是已批准事项。密钥白名单、账号/密钥停用和限流不因此取消；预算按 F03 的后续决定单独移除。
- 最终验收范围：不再提供用户组管理功能；本轮没有新建一套用户/分组体系；运行授权影响及兼容策略明确、可验证。

## F03 · 已确认：移除预算；密钥固定归属、本人签发

### 预算部分：已确认移除

- 用户决定原文：“预算和上一条一样，先去掉”。
- 本轮移除预算管理入口、预算配置操作和个人预算展示，不再投入预算归属编辑的修复或新增转移功能。
- 移除范围包含预算准入限制，不能仅隐藏界面却继续因旧预算规则拦截请求；最终实施计划须列清运行期依赖与兼容处理。
- 保留实际用量、调用结果、成本/积分统计与历史账本；预算移除不等于停止计量、删除历史记录或取消价格配置。
- 不连带移除 API 密钥、鉴权、账号/密钥停用、RPM/TPM/并发限流等独立能力。
- 默认保留旧预算数据供后续设计使用，不做未经确认的破坏性数据库清理。

### API 密钥部分：已确认

- 用户决定原文：“是的，而且admin不能给其他用户创建密钥”。
- 所有角色，包括管理员，只能为当前登录的本人创建密钥；管理员仍可为自己创建，不得代其他用户签发。
- 创建界面不提供选择其他所属用户的能力；服务端根据认证会话确定归属，不能信任客户端传入的用户 ID。任何接口路径均不得通过传入他人的 ID 实际创建他人的密钥。
- 创建后归属固定。界面编辑时归属只读；后台若试图更换归属，明确拒绝，不再假报成功。传入原有同一归属可按兼容契约处理。
- 名称、到期、白名单和启停等原有独立可编辑字段不受影响，不移动历史调用/账本归属。
- 需要换使用者时由新使用者自行创建新密钥，迁移调用后停用旧密钥；不建设密钥转移或管理员代签流程。
- 本条不擅自删除管理员对现有密钥的其他既有管理能力；查看/停用他人密钥的具体展示和范围在 F10 再对齐。
- 验收：管理员和普通用户均只能创建本人的密钥；伪造他人归属不能签发；归属变更被明确拒绝；保存响应与再次 GET 的结果一致。
