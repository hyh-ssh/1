# omni-gateway 产品体验与业务闭环评估

- 日期：2026-10-02
- 对象：用户已打开的 `https://omni.zjic.org/`
- 源码核验基线：`6ccfb89`，分支 `feat/admin-oidc-config`。该基线与最新开发日志一致；线上未读取构建版本，不能断言部署与工作树完全同版。
- 方法：使用现有已登录管理员标签页，检查全部 13 个导航入口、主要新建表单和模型/路由/请求详情；前端 explorer 与业务规则 explorer 分别只读核验角色流程、授权计费依赖，独立 code-reviewer 复核高风险判断。
- 边界：不保存配置、不创建密钥、不停用/删除资源、不点击连接验证/模型发现、不发送模型请求、不读取请求正文、不退出当前会话。普通用户页面基于源码核验，未切换到普通用户实测。完成浏览后恢复原来的「用户」页。

## 一、结论

**这是一套已有较完整网关能力的技术管理台，但还不是任务闭环清晰的组织级模型服务产品。**

主要问题不是缺少更多 CRUD 页面，而是：

1. **保存成功不代表上线就绪**：供应商、模型、别名、路由、价格、分组分别配置，缺少一个能解释最终可用性的统一视图。
2. **调用成功不代表结算成功**：线上已存在有实际用量、缺价格、没有账本记录的成功请求，首页和列表的零成本容易被误读。
3. **登录成功不代表权限已经合理分配**：默认授权与分组撤销语义不直观，新用户没有明确的入站策略。
4. **能看到记录不代表能够解决问题**：详情呈现位置、诊断过滤、有效权限、预算剩余、变更影响面都存在断点。

产品定位按 README 的「单组织内部 LLM 网关」评估。**积分是独立的内部消耗单位，不是人民币余额；无需为了补环引入充值、商城或商业订阅。**

## 三、问题清单与补环方案

### F01 · 缺价成功请求被零成本掩盖（生产账务场景 P0）

- **证据**：B01、B02。详情已经有缺价说明，不能说系统完全不提示；问题在于列表/首页的主状态和后续处理。
- **影响**：管理员可能把「¥0 / 0 积分」理解成免费或无消耗。对已设置预算的用户，后台预算依据账本求和，缺价请求没有对应金额消耗，金额/积分预算无法反映这部分实际用量；不等于请求数/Token 限流也失效。
- **建议**：分别展示「请求结果」和「结算结果」；未定价金额用「未结算」而非普通 0；提供缺价筛选、受影响模型/请求聚合和预填定价入口；模型发布前检查价格，合法免费使用必须显式标记。
- **验收**：出现一次 `unpriced` 时，首页可见可操作告警；列表可筛出；管理员可直接进入对应模型价格配置。补价只解决后续计费，历史是否补账、按哪个版本补账必须另立规则，不能假定自动恢复。
- **源码**：`backend/internal/gateway/records.go:303-317`；`backend/internal/store/budget.go:85-92`；`frontend/src/OperationsPane.vue:95-97,119`。
- **2026-10-02 确认的实施边界**：本轮只实现「显式零费率、免费调用仍完整记录用量」，不是本节全部建议。明确配置的零费率有正用量时仍写入含数量、价格版本的零金额账本；合法零成本/零积分不属于缺价，也不触发零积分误报。成本与积分独立，双零不增加两类预算消耗，但不绕过已有预算准入和 RPM/TPM/并发限制。没有价格仍为 `unpriced`，历史走查 B01/B02 保留原结论。本轮不增加缺价拦截、全局结算状态、筛选告警、自动补账，也不修改线上配置。

### F02 · 默认授权与撤销授权方向不直观（条件性 P0 / P1）

- **证据**：B06。源码确认：无分组成员关系则不限制模型；有关系才按启用组的授权集合限制，再与密钥白名单取交集。OIDC 首登创建启用的普通账号，不自动配组、预算或限流；自建密钥白名单可为空。
- **影响**：普通账号并不是管理员，但在无组、无白名单限制时，其密钥具有所有启用别名的模型访问权限。移除最后一个组可能比留在受限组权限更大；停用已有组可能使有效授权变成空集。若管理员把“移除组”当作撤权，会得到相反效果。
- **建议**：明确选定组织默认策略。限制性组织采用默认基础组/待授权状态及默认配额；保留全员可用策略时，也要显著说明。保存前展示「变更前后有效模型数/名单」，移除最后一个组和空授权给出定向警告。
- **验收**：新用户创建密钥前能看到有效权限；任何组变更都能预览实际权限结果。如果产品要求新用户必须获批，未经授权不能调用。
- **分级**：若企业用户不能默认访问所有模型，P0；若全员授权是明确产品政策，属于 P1 的语义与防误操作问题。不是已经证实的越权攻击。
- **源码**：`backend/internal/store/groups.go:258-277`；`backend/internal/httpapi/api_key.go:135-151`；`backend/internal/httpapi/oidc.go:250-255`；`backend/internal/store/oidc.go:72-89`。

### F03 · 预算/密钥归属编辑与持久化不一致（P1，源码确认）

- **事实**：预算 PATCH 接受新 `user_id`、写入内存对象并按该对象返回成功；更新 SQL 不更新 `user_id`。管理员密钥 PATCH 同样接受并回显新归属，但更新 SQL 不持久化归属。
- **影响**：管理者以为额度已转给另一个账号，实际归属仍是原账号。前端刷新可能显示旧值，但错误的成功响应本身就破坏了操作可信度。
- **建议**：明确归属可否变更：允许则真正持久化并记录审计；不允许则锁定字段且 API 显式拒绝。不要接受后忽略。
- **验收**：改归属后的 PATCH 响应和再次 GET 一致；若不可变则返回明确错误。为该行为补回归测试。
- **边界**：未执行生产写操作，未以线上账号复现。
- **源码**：预算为 `backend/internal/httpapi/admin.go:1097-1123` 对比 `backend/internal/store/budget.go:71-76`；密钥为 `backend/internal/httpapi/admin.go:324-343` 对比 `backend/internal/store/apikeys.go:76-78`。

### F04 · 模型上线缺少跨配置就绪检查（P1）

- **证据**：B05；菜单把供应商、别名、路由、价格、分组拆开。新建别名只填名称，路由和定价另行维护。
- **影响**：能保存的零件不一定构成可用服务。管理员无法在一个页面回答「这个对外模型是否有可用路由、支持哪个协议、是否有价格、谁能调用」。
- **建议**：以“对外模型”为主对象，显示路由、供应商健康、协议能力、计费、授权状态；提供从供应商选择/验证、模型选择，到别名、路由、定价和发布的渐进式流程。支持未完成的草稿，不把草稿等同已发布模型。
- **验收**：任一缺项都有具体原因与补配置入口；“供应商可用”不再被当作“整个模型就绪”。自定义上游模型允许显式覆盖，不要一律强制模型发现成功。
- **源码**：`backend/internal/httpapi/admin.go:854-871`；`backend/internal/store/routing.go:98-105`；`frontend/src/OperationsPane.vue:113,122-123`。

### F05 · 请求详情在长列表底部，点击没有可见反馈（P1，实测）

- **证据**：B03。
- **影响**：用户很容易以为按钮无效；手动滚动找详情后，又失去列表位置、筛选条件和侧栏导航。50 条记录每条卡片约 91px，低信息密度放大该问题。
- **建议**：桌面采用侧边抽屉或独立详情页，保留筛选/分页/滚动位置；至少把详情滚入视口并转移焦点；请求列表改为紧凑表格。
- **验收**：点击任意行，详情在当前可见区域出现；键盘焦点可达，关闭后返回原行；不必滚过全部 50 条记录。
- **源码**：`frontend/src/OperationsPane.vue:119-124`。

### F06 · 预算显示规则，不显示真实的可用额度（P1）

- **事实**：管理员配置的是用户级成本/积分上限；成员页展示上限与窗口秒数，没有当前窗口已用、剩余、接近上限警告，也没有提额/联系管理员的闭环。
- **影响**：用户无法判断还能用多少、被拦后何时可能恢复；终身累计用量不能替代当前滚动窗口的消耗。
- **建议**：展示「过去 24 小时（滚动）」等可读周期，分开显示人民币成本与积分的已用/上限/剩余；提供临界提示、阻断原因和提额入口。可先链接组织现有工单，不必新增审批平台。
- **验收**：规则、可用额度与准入判定使用同一口径；明确滚动窗口不是每天零点统一清零。恢复时间只能按历史消耗给出估算，不能保证一个固定重置时刻。
- **源码**：`frontend/src/App.vue:366-367,767-779`；`backend/internal/store/budget.go:85-92`；`backend/internal/httpapi/self.go:120-168`。

### F07 · 普通用户拿到密钥后仍缺接入指引与有效模型列表（P1，源码核验）

- **事实**：成员视图有账号、密钥和记录，但没有 base URL、可复制的 SDK/curl 示例、可用模型列表或“首次调用已成功”的引导。白名单为空时显示“全部模型”，没有说明仍受组授权约束。
- **影响**：新用户无法独立回答「地址填什么、模型叫什么、我能用哪个协议、为什么此模型返回 403」。这是接入闭环缺失，不是密钥生成能力缺失。
- **建议**：增加「快速接入」：地址、兼容协议、有效模型、请求样例、密钥保存提示和首调验证状态。默认做静态配置检查；真实测试调用应明确可能产生用量并由用户触发。
- **验收**：普通用户不需向管理员询问模型名和地址即可接入；显示的是最终有效权限，不是仅显示密钥白名单。
- **源码**：`frontend/src/App.vue:373-383,743-800`；`backend/internal/httpapi/api_key.go:135-151`。

### F08 · 失败诊断与检索尚未形成自助闭环（P1）

- **事实**：成员记录只渲染模型、成功/失败、用量耗时，不呈现返回的错误原因和 request ID；硬编码最近 50 条。管理员请求页虽有分页和详情，但没有时间、密钥或结算异常筛选；审计页只刷新，无分页/筛选。
- **影响**：普通用户无法区分权限、额度、上游故障；管理员难以定位某密钥某时段的异常。管理 API 错误封装在前端只保留 message，丢弃 code/request_id，支持交接也失去关联标识。
- **建议**：成员页显示安全的错误分类、说明、下一步和可复制 request ID；管理员加时间/密钥/结算状态过滤；错误提示保留结构化标识；审计增加检索分页。无需为了自助排障默认开放敏感正文。
- **验收**：用户遇到 403/429/上游失败时能知道处理责任方；管理员能按 request ID 或密钥+时间找到对应链路。
- **源码**：`frontend/src/App.vue:793-800`；`frontend/src/api.ts:49-52,117`；`frontend/src/OperationsPane.vue:110,118`；`backend/internal/httpapi/admin.go:1386-1412,1503-1560`。

### F09 · 变更/删除缺少业务影响面，审计不能还原变更（P1）

- **事实**：供应商/别名删除已有确认，也明确提示路由级联删除；不足是没有列出受影响别名、用户、调用量及“删除后无路由”的结果。审计记录对象路径、方法和操作者，但 detail 通常只是 `admin API mutation`，没有 before/after。
- **影响**：知道谁操作过，不等于知道具体改了什么、影响了哪些使用者。事故难以归因或还原配置。
- **建议**：变更前预览影响面；最后一条可用路由/最后一个授权组等高风险操作特别警告；优先建议停用。审计保存不含凭据的变更摘要与受影响对象。
- **验收**：删除供应商前可见具体影响，关键配置变更可追踪前后值；敏感字段只记“已变更”，不记录明文。
- **源码**：`frontend/src/OperationsPane.vue:88-90`；`backend/internal/httpapi/admin.go:1590-1606`；`backend/internal/store/providers.go:86-89`。

### F10 · 密钥生命周期在两种角色下不一致（P1 / P2）

- **事实**：成员端已有一次性明文弹窗、复制、掩码、最后使用、停用/删除。管理员新建却把明文放在提示条，没有同样的复制/确认流程；管理列表不展示过期与最后使用。成员端没有修改名称、到期时间或白名单的入口，后台已有部分编辑能力。
- **影响**：签发者易漏存唯一一次明文；管理员难以治理将过期/闲置密钥；成员不能顺畅收窄范围或维护现用密钥。
- **建议**：两角色复用一次性密钥弹窗；治理列表显示过期、最后使用、负责人；给成员开放已有安全编辑能力；提供“先建新—验证迁移—停旧”的轮换引导。
- **验收**：任何角色都能正确保存并关闭唯一一次明文；无需直接删旧密钥才能完成迁移。
- **不作断言**：未创建生产密钥，未证实“停用后旧明文再次出现”；不将该推断写为线上泄漏。
- **源码**：`frontend/src/App.vue:571,626-635,742,787,847-856`；`backend/internal/httpapi/self.go:299-337`。

### F11 · 高影响表单以数据库字段/JSON为中心（P1 / P2）

- **证据**：B04、B05。
- **影响**：手填用户 ID 容易选错归属；秒数不符合业务思维；价格小数无法直接判断每百万 Token 的金额；成本与积分不能相互换算却缺少解释。不可变价格一旦配置错误，还要创建新版本纠正。
- **建议**：预算与密钥复用限流已有用户选择器；白名单/模型 ID 用模型选择；周期提供预设并保留高级自定义；价格用计量项、单位、费率表格，展示样例请求的成本/积分试算，JSON 仅作高级模式。
- **验收**：不用记 ID、写 JSON 或手算秒数也能完成常规配置；明示 CNY 与积分是两本独立账，价格版本生效规则清楚。
- **源码**：`frontend/src/App.vue:809,812-824`。

### F12 · SSO-only 用户看到无法完成的修改密码操作（P1，源码确认）

- **事实**：OIDC 新账号的本地密码是无人知道的占位随机凭据，本地密码登录关闭；成员页无条件显示“当前密码/修改密码”，修改接口却要求验证当前密码。
- **影响**：SSO 用户没有可填写的“当前本地密码”，不能独立走完表单；也不应诱导其输入企业 IdP 密码。
- **建议**：根据登录来源/密码登录标记呈现能力：SSO-only 用户显示“密码由统一身份源管理”，提供组织说明或身份源入口；如允许添加本地登录，另设计受控初始化流程，不能复用当前密码表单。
- **验收**：SSO-only 账号不再看到不可完成的本地改密表单；具有本地密码的账号仍可改密且注销其他会话。
- **源码**：`backend/internal/store/oidc.go:72-89`；`frontend/src/App.vue:757-765`；`backend/internal/httpapi/self.go:388-395`。

## 四、建议优先建立的四条闭环

1. **模型上线**：添加供应商 → 验证/选择模型 → 建别名和路由 → 定价或明确免费 → 授权 → 就绪检查 → 发布 → 监控。
2. **用户接入**：登录/自动建号 → 明确默认权限与配额 → 查看有效模型 → 创建并保存密钥 → 复制接入配置 → 首次调用 → 看到结果。
3. **用量预算**：配置规则 → 展示当前窗口消耗与剩余 → 接近上限提示 → 被拦原因及恢复预期 → 提额/调整 → 审计与验证。
4. **故障修复**：首页异常 → 可筛选的受影响请求/模型 → 请求与上游尝试/账务分层归因 → 进入对应配置 → 安全修复 → 验证后续结果 → 留痕。

## 五、实施排序

### 第一批：先使状态可信、控制生产风险

- 区分成功/结算成功；未计费主视图可见，新增缺价处理入口。
- 明确新用户默认授权策略；对移除最后组、空授权预警。
- 修复或禁用预算/密钥归属的无效编辑。
- 请求详情改抽屉或至少定位到可见区域。

### 第二批：让管理员和用户能够独立完成常规任务

- 建立模型就绪汇总和渐进式接入流程。
- 展示有效模型、接入示例、预算剩余和失败原因。
- 用户/模型选择器、可读周期、价格表格与试算。
- 统一密钥流程，处理 SSO-only 账号的能力差异。

### 第三批：运营可治理、事故可追溯

- 时间/密钥/结算状态过滤，审计分页与 before/after。
- 删除/停用影响面分析、配置深链、上下文恢复、统一加载状态。
- 可选：复用现有组织工单完成授权/提额申请，不必先扩建完整工单系统。

## 六、应该保留的现有能力

- 管理员与普通用户界面/API 分离；个人接口以会话账号为准，防止通过传入别人的 ID 越权。
- 成员密钥一次性明文、掩码、复制与最后使用；密钥停用即时生效。
- 主 OIDC Provider 的客户端密钥只写不读，留空保留，清空同时停用。
- 请求可关联上游尝试、用量与不可变账本；缺价结算已有具体说明。
- 内容日志默认不保存，读取前有敏感信息确认并审计。自助诊断不要破坏该边界。
- 价格版本不可变，成本与积分分账；故障转移在输出开始后不再切换。
- 删除已有二次确认；供应商已有验证、发现和健康状态，不应重造这些能力。
